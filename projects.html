Projects

Four builds, four different constraints.

Each project below was built as a complete system rather than a proof of concept — with auth, error handling, and (where relevant) a working LLM integration.

RAG Compliance Document Assistant

Portfolio project

A document-grounded question-answering system built to demonstrate retrieval-augmented generation end to end, not just a chat wrapper. The prototype runs client-side TF-IDF retrieval, calls the Claude API for generation, and stamps every answer with citations back to source passages.

Beyond retrieval, it simulates role-based access control at query time — so a user without clearance to a document can't retrieve grounded content from it — and keeps a running audit log of every query and the sources it touched, which matters a lot in a compliance context.

Key design decisions

  • Chunking strategy tuned for compliance documents rather than general text
  • Citation enforcement to reduce hallucinated answers
  • RBAC checked at retrieval time, not just at the UI layer
Stack
HTML/JS, TF-IDF, Claude API
Role
Solo build
Status
Working prototype

College ERP Portal

Most expansive build

A full-stack college administration system covering three distinct user roles — Admin, Faculty, and Student — each with its own dashboard and permission boundaries. Built module by module: authentication first, then core records, then reporting.

The data layer spans 19 Prisma models. Auth uses JWT with rotating refresh tokens rather than long-lived access tokens, and file uploads (assignments, documents) go through Cloudinary. The frontend includes Recharts-powered dashboards and an in-app notification system.

A real problem solved

Cloudinary v1/v2 conflicted with the multer-storage-cloudinary integration during the build — resolving that dependency mismatch was part of getting file uploads working reliably.

Stack
React, Vite, Tailwind, Node.js, Express, PostgreSQL, Prisma
Scale
19 data models, 3 roles
Status
Complete

MemoryVault

Side project

A private photo and video sharing app for a close friend group — built out of an actual need rather than as a portfolio exercise. Uploads go to S3-compatible storage (AWS S3 or Cloudflare R2) behind signed URLs, so media stays private to the group.

Auth uses JWT with bcrypt-hashed passwords, and Nodemailer handles notification emails. A Docker Compose setup makes local development reproducible across machines.

Stack
React 18, Node.js, Express, PostgreSQL, AWS S3 / R2
Auth
JWT + bcrypt
Status
Complete, deployment in progress

NL2SQL Enterprise Analytics Tool

Earlier build

A conversational analytics dashboard that turns natural-language questions into SQL queries against a real database, with a security layer to prevent destructive or out-of-scope queries from executing.

Originally built around the Claude API with forced tool calling, then refactored into a multi-provider architecture supporting both Claude and Gemini — a shared schema and base engine class, with provider-specific implementations underneath.

Stack
SQLAlchemy, SQLite, Streamlit, Claude API, Gemini API
Notable
Multi-provider engine architecture
Status
Complete
